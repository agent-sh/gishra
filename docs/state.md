# State

gishra keeps a project's plan and progress in plain files. People and dashboards read them; only the `gishra` CLI writes them, under a lock, after validation. An agent that needs to change state runs a command.

## Where

The state directory is the first of:

1. `--state DIR` on the command line
2. `GISHRA_STATE` in the environment (`gishra spawn` sets it for every agent it starts)
3. `.gishra/` at the root of the main checkout, found through `git rev-parse --git-common-dir`, so every worktree of the repo shares one state

`gishra init` adds `.gishra/` to `.git/info/exclude`. State is not committed unless the project chooses to.

## Files

| File | Holds |
|---|---|
| `project.json` | name, goal, repo, base branch, roles, limits, budgets, standards profile |
| `tasks.json` | every task and its status, evidence and spend |
| `decisions.json` | questions for the owner and their answers |
| `briefs/<task>.md` | the context a worker gets for that task, kept current by the orchestrator |
| `events.jsonl` | append-only log of every change, with time and agent |
| `sketch.md`, `sketch.html` | rendered views; regenerated by `gishra render` and after every write |
| `lock` | advisory lock file; never edit |

All JSON files carry `"version": 1`. Writes go to a temp file in the same directory and are renamed into place.

## project.json

```json
{
  "version": 1,
  "name": "billing-retry",
  "goal": "Retries on payment webhooks are idempotent and observable",
  "repo": "acme/billing",
  "base": "main",
  "standards": "default",
  "roles": {
    "orchestrator": { "harness": "claude", "model": "claude-opus-5-5" },
    "worker":       { "harness": "codex",  "profile": "sol" },
    "reviewer":     { "harness": "claude", "model": "claude-opus-5-5" },
    "small":        { "harness": "codex",  "profile": "luna" }
  },
  "limits": { "workers": 6, "lease_minutes": 60 },
  "budget": { "hours": 40, "tokens": 20000000 }
}
```

A role names a harness and a model or harness profile. `harness` is one of `claude`, `codex`, `opencode`, `gemini`, or `command` with a `command` array (`{task}`, `{brief}`, `{prompt}` and `{cwd}` are substituted). `standards` is `default` (the profile shipped with gishra) or a path to a Markdown file.

## tasks.json

```json
{
  "version": 1,
  "next": 4,
  "tasks": [
    {
      "id": "T1",
      "title": "Idempotency key on webhook retries",
      "kind": "code",
      "acceptance": ["a retried webhook with the same key is processed once", "test proves it"],
      "depends_on": [],
      "needs_owner": null,
      "size": "M",
      "role": "worker",
      "status": "todo",
      "claim": null,
      "branch": null,
      "pr": null,
      "sha": null,
      "evidence": [],
      "revision": 1,
      "spend": { "minutes": 0, "tokens": 0 },
      "notes": []
    }
  ]
}
```

- `kind`: `code`, `docs`, `research`, `design`, `ops`.
- `size`: `S` (under an hour), `M` (a few hours), `L` (a day). Anything larger is split; `validate` reports it.
- `needs_owner`: null, or the reason the owner has to act (a credential, a purchase, a product call). Such a task is never ready on its own; the owner clears it with `gishra owner-done`.
- `status`: `todo`, `in_progress`, `submitted`, `accepted`, `rework`, `cancelled`. `ready` and `blocked` are computed, never stored.
- `claim`: `{ "agent": "w-3", "since": "...", "until": "..." }` while in progress. An expired lease frees the task.
- `evidence`: entries `{ "type", "ok", "sha", "agent", "at", "summary", "ref" }`. Types: `tests`, `clean`, `review`, `ci`, `merge`, `note`.
- `revision`: incremented when acceptance or dependencies change; evidence recorded against an older revision does not count.
- `notes`: `{ "at", "agent", "text" }` entries. The orchestrator folds what matters into the brief.

### Ready and blocked

A task is ready when its status is `todo` or `rework`, every dependency is `accepted`, `needs_owner` is null, and no open decision lists it in `blocks`. Otherwise `gishra ready --all` says what blocks it.

### Acceptance gates

`gishra accept` refuses unless the task's current revision has, at the submitted `sha`:

- `code` tasks: `tests` ok, `clean` ok, `review` ok from an agent other than the one that submitted, and `ci` ok when the task has a PR
- other kinds: `review` ok from another agent

The standards profile may add gates. `--waive TYPE --reason TEXT` records an owner waiver as evidence; only an agent named `owner` can waive.

## decisions.json

```json
{
  "version": 1,
  "next": 2,
  "decisions": [
    {
      "id": "D1",
      "question": "Store idempotency keys in Redis or Postgres?",
      "options": ["redis", "postgres"],
      "recommendation": "postgres",
      "why": "keys must survive a Redis flush; volume is 30/s",
      "blocks": ["T3"],
      "status": "open",
      "answer": null,
      "asked_by": "orchestrator",
      "asked_at": "...",
      "answered_at": null
    }
  ]
}
```

A decision blocks only the tasks it lists. Everything else keeps running.

## events.jsonl

One JSON object per line: `{ "at", "agent", "cmd", "task", "detail" }`. `gishra status` and the sketch read time and token spend from tasks; the log is for audit and recovery.
