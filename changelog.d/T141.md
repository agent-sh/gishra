- `gates prioritize ID --reason R` (operational: the orchestrator or the owner) moves a task's queued gate reactions ahead of older queued work, so the next free executor takes them first. Each request logs a `gates prioritize` event with its reason; a request for a task with nothing queued is refused.
- `status` shows the gate queue: running tasks, then queued tasks in the order executors take them, with any prioritized task marked and its reason. `status --json` carries the same as `gate_queue`.
