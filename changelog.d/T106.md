- Sandboxed claude and codex agents cannot read the user's credential stores: gh, claude, codex, docker, npm, pypi, cargo, netrc, git-credentials, kube, gcloud, azure, ssh and aws, through Bash (claude's sandbox) and claude's Read, Grep and Glob tools (Read deny rules). Before, claude hid only `~/.ssh` and `~/.aws` and codex hid none, so a worker could read the gh login, the model credentials and registry tokens and send them anywhere. A store holding the agent's house rules, such as `~/.codex/AGENTS.md`, hides its other entries. Sandboxed homes no longer link `.config/gh`; gh uses the handed `GH_TOKEN` and its own config directory even when the user sets `GH_CONFIG_DIR` or `XDG_CONFIG_HOME`.
- Denials follow credential-location overrides, including every `KUBECONFIG` entry, and cover Tower Crane config and Pi/Agy credential files. Repository rule imports cannot create read exemptions; imports resolving to protected credentials refuse startup before the harness runs.
- Symlinked credential targets are protected even outside a store. Environment overlays retain the original, project, route and selected env-file locations in the deny list. The supervisor enforces gh's isolated config after settings on initial, retry and fallback launches.
- The escalation test wait helper evaluates its predicate after reading the ceiling, preventing false failures when an expected owner decision appears between reads.
- Credential discovery includes Claude settings, Codex dotenv assignments and resolved provider launch paths, so custom AWS files remain hidden when the harness supplies their locations.
